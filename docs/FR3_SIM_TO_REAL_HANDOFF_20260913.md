# FR3 语义安全推动：仿真实现与真机部署交接

更新时间：2026-09-13。交接对象：**FR3 + 原装闭合夹爪**，首批真机物体为锤子、螺丝刀、剪刀。

## 1. 从哪里开始

使用仓库的 `releases/fr3_semantic_20260913/`。这是从实际测试的 `source_choice_eval_v1` 导出的独立仿真版本，79 个控制器／环境文件与原冻结源逐文件一致，`source_manifest.json` 保存 SHA-256。它有独立入口、场景、语义资产、审计和测试；仓库根目录还保留其他历史实验。

先读 [发布说明](../releases/fr3_semantic_20260913/README.md)，运行 `run.py`。该入口**只执行仿真，不连接机器人**。当前没有完成从 RGB-D/VLM 到真机推动的整条链路，不能把此目录当成已经调好的真机控制包。

原始日志：`outputs/fr3_semantic_map_20260913/`。发布目录的 `evidence/` 保存精选视频、统计与核验证据；大体积逐物理步日志留在仿真服务器。已知开发回归和新布局留出测试分别报告。

## 2. 当前方法的完整流程

1. **工具模型和部位语义**：canonical mesh + safe/protected 标签；仿真使用 DOMINO 模型与既有标注。
2. **场景状态和关系语义**：读取目标、杂物的位姿以及机械臂状态；助手根据场景／用户任务提供缓存规则，杯子与气球 forbidden，布偶 acceptable。
3. **候选接触与短预测**：生成安全部位接触、推动方向和距离，计算可实现的接触伺服方向与力矩。任务代价和地图代价使用同一名义方向，避免“评分方向与执行方向不同”。
4. **几何约束和代价排序**：C1 部位接触限制；目标整体三维扫掠的杂物检查；机械臂全几何路径检查。禁碰作为硬拒绝；允许接触产生有限代价。
5. **执行与反馈**：IK 到接近／接触位置，维持有效接触，执行短推动，观察物体变化，必要时释放与重新规划。
6. **独立验收**：逐物理步记录真实位姿、力和夹爪状态，复算终态持续时间、违规、代价查询以及来源校验。

| 模块 | 发布目录内入口 | 可复用内容 / 需要替换的部分 |
|---|---|---|
| 主循环、候选与伺服 | `scripts/run_contact_planner_m1.py` | 保留规划思路；当前直接依赖 IsaacLab scene 数据 |
| 接触策略与在线地图接口 | `scripts/fr3_semantic_cost_map.py` | policy、候选评分；替换 live pose/mesh、接触传感读取 |
| 全目标三维扫掠 | `scripts/fr3_semantic_sweep3d.py` | 基于 FCL 的几何查询可以复用 |
| 全臂与接近／撤退检查 | `scripts/fr3_execution_runtime/` | 几何与路径逻辑可复用；机器人关节、TCP、场景坐标需实测对齐 |
| FR3 仿真配置与日志 | `scripts/m1_fr3_comparison_adapter.py` | 仿真专用，不能复制为硬件驱动 |
| 独立验收 | `scripts/audit_fr3_semantic_demo.py` | 指标定义可复用；仿真力与真机力证据应分开 |

这是简化模型下的候选预测与接触反馈控制，不是原版 Push Anything/C3+ 求解器，也不是训练好的 RL 策略；运行不需要策略 checkpoint。

## 3. Semantic cost map 到底做了什么

地图的三维点查询使用物体语义体积。禁碰物体的保守凸包包含杯子的空腔；允许接触物体使用实际凸碰撞部件的并集。距离带 δ=12 mm，布偶的基础有限权重 w=0.15。

对于候选预测扫掠，取各物体在整个短时域内的最小距离 d，再计算 `sum(w * clip(1-d/δ, 0, 1))`。只要任一禁碰物体的距离不大于 δ，该候选被拒绝；更好的任务代价不能抵消它。

保留候选的总代价为 `J_task + λ * J_semantic`。开发试验后冻结 λ=0.5 m，基线 λ=0；两组共享硬约束。λ 的单位用于匹配现有任务评分，它不是损伤概率或接触力标定。

控制器在线查询当前三维几何，不从绘制的热力图读取像素。三维点地图、完整目标位姿扫掠代价、全臂构型检查是不同查询；C1 与全臂硬检查仍独立。当前有限代价针对目标—允许物体接近，不是全臂接触力优化。

已有证据表明代价可以改变实际接触选择；不能保证峰值力总是下降，也不能保证任意新布局均能找到绕行。刚体布偶／气球／杯子没有柔性、爆破或流体仿真。

## 4. 控制频率、动作与坐标：真机接入的关键边界

- 物理频率 **240 Hz**，每个动作 12 个物理步；动作／关节位置参考 **20 Hz**，50 ms 一次。
- 外层重规划由事件触发，不等于每 50 ms 必定求解一次。原微推动时域约 0.3 s，名义微位移约 2 mm。
- 目前执行层是 **latched joint-position + 原 PD 增益 + 重力补偿**，不是本项目早期 C3 的力矩 OSC。20 Hz 是上层参考频率，不应把真机底层伺服也降至 20 Hz。
- `env.step()` 接收的是缩放后的关节动作，不能直接传给真机。硬件适配器应使用物理单位的 7 维绝对 `q_target_rad`，明确起始关节、关节顺序、时戳和有效期，并交由部署仓库已有插值／限幅与底层会话处理。
- 内部名称仍有 `panda_joint1..7` 别名，但实际模型是 FR3；不能因变量名为 panda 改回 Panda 机械参数。
- 位姿日志为 `[x,y,z,qw,qx,qy,qz]`，位置单位 m，关节与旋转单位 rad。SciPy 为 xyzw，转换已经显式处理。SO(3) 误差是完整相对旋转角，不是只取 yaw。
- 必须核对 `T_base_camera`、`T_base_object`、mesh 的 canonical 坐标和 TCP。仿真环境原点、机器人底座 +29 mm 修正、`.1034 m` 末端几何偏移属于当前模型的具体定义，不能直接当作现场标定数值。
- 机器人模型与夹爪几何在 `data/robot_models/fr3_stock_20260909/`；真机需要实际原装夹爪的质量、惯量、TCP 与关闭状态，不能沿用 RH56 的负载与工具变换。

建议的硬件边界数据（接口设计，尚未实现整链路）：

```text
SceneState:
  monotonic_timestamp, frame_id, q_rad[7], dq_rad_s[7]
  T_base_tool, T_base_obstacles[], pose_validity/uncertainty
  goal_pose, canonical_geometry_version, semantic_policy_version

PushReference:
  sequence, source_state_timestamp, valid_until
  q_target_rad[7], phase, contact_id, expected_contact_direction
  constraint_verdicts, reason_if_hold_or_stop
```

接触力证据在仿真中来自 PhysX 分物体传感器；真机一般无法直接得到完全等价的“某个锤子部位—某个布偶”的力矩阵。必须明确使用外力估计、触觉、视觉接触判定中的哪一种，不能照搬仿真传感器阈值并声称等价安全验证。

## 6. 先拍真机 demo 的接入顺序

1. 选一把有匹配 mesh／明确 safe 部位的锤子，先核对桌面、相机、物体和 TCP 坐标。螺丝刀、剪刀各自建立真实模型与部位定义，不复用锤子参数。
2. 用录制的真实相机／机器人状态离线驱动规划，输出候选、预测扫掠、拒绝原因和 q_ref；先确认这些参考在实际机械臂工作区内。
3. 接现有硬件会话，用短距离接近／撤退验证关节顺序、TCP、位置参考解释与跟踪。相机状态过期或规划超时不能继续沿旧接触参考推动。
4. 无杂物单次短推，比较预测与实测平移／旋转，辨识真实工具的质量、重心与接触响应。仿真锤子 mass=0.05 kg、摩擦=0.3 不能无测量地照搬。
5. 单个明确禁碰障碍，再添加可接受接触布偶；同步保存真实视频、位姿、参考、语义规则和接触证据。VLM 可在初始化/场景事件时产生规则，跟踪和控制维持独立时序。

上面是部署接入计划，不表示本次上传已经完成这些硬件测试。当前最明确的限制是新角度／相对布局泛化不足；应先选经过仿真验证且现场几何匹配的短任务拍 demo，同时保留未成功案例。

## 7. 结果和验收口径

已知布局开发回归：hard 与 soft 均 20/20，4 个布局各做 5 个整体平移；不是 20 个独立复杂任务。可选接触布局的布偶接触峰值中位数 0.02014 N→0；侧方布局接触时长 22.90→13.59 s，但 2 场峰值力增加。

新相对布局／角度留出：**hard 5/20（25%），soft 4/20（20%）**，40 场全部有效且独立审计通过，无检测到的 C1 或禁碰违规。该数据与开发回归分开，权重没有事后调整。每场杂物独立平移／旋转，目标为 −30°、−15°、20°、35°、50°。完整逐场结果见发布目录 `evidence/holdout20/RESULTS.md` 和 `aggregate.json`。

两组共同失败的场景有 15 个，表现包括推动后姿态未收敛、位置仍未到位，以及未建立接触就退出。仅 soft 失败的 001 已到位并保持约 2.19 s，但没有 >0.5 N 的安全接触证据；按既有 0.02 N 门槛补充统计，两组均为 5/20。不能把主要泛化失败归因于这一个验收门槛，也不能仅凭这些终态数据断言都是动力学模型问题。

严格成功：终态 XY<20 mm、Z<10 mm、SO(3)<0.105 rad 持续至少 0.5 s；夹爪闭合、无 C1/禁碰违规，且沿用历史的至少一次 >0.5 N 安全部位机器人—目标接触证据。控制器接触门槛为 0.02 N。部分任务到位但缺少 0.5 N 证据，会按冻结标准判失败，报告额外单列已有 0.02 N 证据下的到位结果，不替换主结果。

坐姿布偶：模型坐高 22.7 cm、宽 17.6 cm，动态质量 0.12 kg。第一版弧面支撑翻倒，已作为场景构建失败保留；第二版臀部和脚底具有平整支撑，10 s 静置通过。新演示严格成功，XY=12.30 mm、SO(3)=0.09871 rad；没有实际接触布偶，因此这段视频证明带较大坐姿物体的场景执行，不证明碰撞后的柔性安全。

效率：前一开发回归不录像完整进程中位约 102 s，对应约 24 s 仿真；录像约 191–203 s。三维扫掠核心查询每场累计中位约 0.046 s，未包含几何构建、读取、日志和全臂检查。不能用 20 Hz 配置推导墙钟实时性，也不能把一次离线任务的进程耗时直接等同于真实机器人任务时长。
