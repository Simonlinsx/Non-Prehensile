# Accepted C1 teacher snapshot

This file identifies the frozen, reproducible C1 result before clutter/C2/C3
development.  It is the concise status document; `AFFORDANCE_TEACHER.md`
retains the full experimental history and rejected ablations.

## Scope

- Target: one DOMINO `020_hammer:0` on a fixed support face.
- Goal: strict planar translation, height, and full SO(3) placement with a
  five-policy-step dwell.
- Randomization: initial target XY, goal displacement/direction, friction, and
  held-out manifest scenes.  The accepted split keeps one stable support
  orientation and has zero relative goal yaw; full SO(3) is therefore a
  stability constraint rather than an independently randomized yaw objective.
- No active clutter.  C2 and C3 code is experimental and has no accepted claim
  in this snapshot.

The deterministic hard-C1 evaluation task is
`Isaac-AffordanceTeacher-FrozenV7-GoalWrench-C1-Franka-v0`.  Its held-out
manifest is
`data/manifests/teacher_direction_curriculum_v10/hammer_teacher_dir45_eval128_seed9833.jsonl`.
Evaluation uses one first terminal episode from each of 128 environments; it
must not repeatedly count fast-resetting easy environments.

The checked-in train/eval manifests use initial `x=0.46--0.50 m`, initial
`y=-0.015--0.015 m`, goal displacement `0.065--0.095 m`, and direction
`-45--+45 deg`.  These measured manifest bounds, rather than a broader planned
distribution, define the accepted claim.

## Policy and safety contract

The actor observation has 4,141 recoverable values:

- 512 target points encoded jointly as `[x, y, z, safe, protected]`;
- 512 obstacle XYZ points (zero/inactive in C1);
- hand pose, Franka proprioception, previous action, relative SE(3) goal, and
  noisy target twist.

The critic additionally receives five exact dynamics scalars and is discarded
at deployment.  Simulator contacts, exact mass/friction, future state, and
reward-only route variables are not actor inputs.

The accepted controller outputs seven relative Franka joint-position actions.
Later six-dimensional Cartesian-control experiments are not checkpoint-
compatible with this frozen snapshot and are not part of the accepted result.

C1 is an episode violation if the hand contacts a non-safe target region or a
proximal Franka link physically contacts the target.  The dense soft term is a
learning signal only; acceptance uses the exact semantic/PhysX event predicate.
Constrained success requires strict pose success and zero C1 events over the
whole episode.

## Reproduction entry points

The generic 1,024-environment trainer is `scripts/train_affordance_teacher.sh`.
For example, a direction-randomized recoverable-observation competence run is:

```bash
OMNI_KIT_ACCEPT_EULA=YES GPU_ID=6 NUM_ENVS=1024 SEED=17 \
TASK=Isaac-AffordanceTeacher-T0-FrozenV7-GoalWrench-Soft-Franka-v0 \
DAPL_CLUTTER_MANIFEST=data/manifests/teacher_direction_curriculum_v10/hammer_teacher_dir45_train256_seed8831.jsonl \
RUN_SUFFIX=c1_direction_competence_from_scratch \
bash scripts/train_affordance_teacher.sh
```

The selected v29/v30 checkpoints are short complete-C1-soft curriculum
continuations of direction-competent checkpoints, not independent random
initializations.  Run the hard deterministic acceptance evaluation with:

```bash
OMNI_KIT_ACCEPT_EULA=YES GPU_ID=6 \
PROFILE=c1_frozenv7_goalwrench_dir45 \
CHECKPOINT=/absolute/path/to/model_359.pt \
NUM_ENVS=128 NUM_EPISODES=128 SEED=17 \
bash scripts/evaluate_affordance_teacher.sh
```

Qualitative randomized videos, including the translucent cyan goal object and
green/red safe/protected overlays, are generated by:

```bash
OMNI_KIT_ACCEPT_EULA=YES GPU_ID=6 \
CHECKPOINT=/absolute/path/to/model_359.pt \
OUTPUT_ROOT=outputs/teacher_demos/c1_accepted_randomized \
bash scripts/render_c1_randomized_demos.sh
```

Video mode alone applies a matte blue-gray support surface and reduced dome
lighting.  Physics, observations, policy outputs, training, and non-video
evaluation are unchanged.

Checkpoints, W&B state, videos, and evaluation outputs remain generated
artifacts under ignored `logs/` and `outputs/` locations; they are not embedded
in the source snapshot.  The selected local checkpoint paths and the full
evaluation provenance are recorded in the current-audit section of
`AFFORDANCE_TEACHER.md`.
